# Accessibility And UX Requirements

## UX goals

- Make the platform calm for beginners.
- Keep provenance visible without overwhelming the learner.
- Let experienced learners move faster without hiding remediation.

## Launch UX requirements

- dashboard with next recommended lesson
- resume last session
- chapter and lesson breadcrumbs
- objective coverage view
- weak-area panel
- review queue panel
- lesson-level source label
- collapsible source evidence area
- confidence capture after checks
- needs-review toggle
- tutor sidebar or panel with clear mode label

## Accessibility requirements

- full keyboard navigation
- semantic heading hierarchy
- visible focus styles
- readable code blocks with copy support
- tables that remain understandable to screen readers
- contrast-safe color system
- no motion required for comprehension
- plain-language mode for dense explanations
- jargon clarification available inline or on demand
- responsive layouts for laptop and tablet widths

## Content presentation requirements

- lessons must declare whether they are source-grounded or bridge content
- gap-limited lessons must show a caution label
- objective ids should be visible in review contexts
- code examples should be short and segmented
- portal workflows should use numbered steps

## Failure-state UX

- if a learner fails repeatedly, offer recovery instead of blame
- if the tutor lacks evidence, say so clearly and helpfully
- if a live lab is unavailable, switch to simulation mode instead of dead-ending

## Launch answer

The first version should optimize for clarity, pacing control, and provenance visibility more than visual flourish.
