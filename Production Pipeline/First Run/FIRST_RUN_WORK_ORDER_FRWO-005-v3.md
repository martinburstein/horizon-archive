## Frozen strict data-URL ingress protocol

Science must independently validate and make executable this complete
prospective protocol before Mission may authorize Quartermaster ordinal `2`.

1. **Future built-in calls only.** Ordinal `1` is never retried, recovered,
   reinterpreted, inspected, decoded, discovered, or cleaned. A future attempt

2. **Fresh exact temp target first.** Before the call, resolve the OS temporary
   parent without listing it; create one fresh GUID-named direct child with
   create-new semantics; prove it is outside the repository and every
   protected, user, browser, save, managed, and residual root; predeclare only
   the exact `attempt-0N.png` target; and prove that target absent. The later
   decode write alone uses create-new semantics. No broad, recursive, pattern,
   parent, or fallback path operation exists.
3. **Exact single result shape.** Accept exactly one built-in result object and
   use exactly one string from its direct `image_url` field. `output_hint` is
   ignored as opaque: never parse, quote, expose, retain, search, or use it.
   Reject arrays, multiple results or payloads, missing or non-string
   `image_url`, alternate or remote URLs, blobs, files, path-like text, or any
   ambiguous shape. Such a transport rejection consumes the ordinal, creates
   no `PHY-01..12` result, and authorizes no additional action except exact
   cleanup of the predeclared empty temp child where safely provable.
4. **Literal data-URL grammar.** The accepted string begins exactly once with
   literal `data:image/png;base64,` and contains exactly one nonempty payload
   after that prefix. Whitespace, line breaks, parameters, percent encoding,
   fragments, secondary commas or separators, non-base64 alphabet, noncanonical
   padding, trailing material, or encoded length above the shell-approved bound
   is rejection. Strict validation precedes decode; MIME spelling or prompt
   intent is never format proof.
5. **Decode once, materialize once.** Strictly base64-decode the accepted
   payload exactly once. Write those decoded bytes exactly once to only the
   predeclared `attempt-0N.png` through create-new semantics. No repository,
   managed, user, browser, save, accepted-media, protected, or residual path may
   receive payload bytes. No second decode, repair, normalization, export,
   derivative, upscale, conversion, or alternate materialization exists.
6. **Payload-to-temp identity.** During the single decode, count decoded bytes

   Any mismatch stops opaque. After identity, discard decoded-memory bytes,
   base64 text, and result references; reference disposal does not prove or
   imply managed-file deletion.
