## Independent viability result

The complete-game Markdown script is viable as a documentation-only slice.
The single rail, local pass/remediation loop, forty-cluster learning order,
four-act dramatic escalation, privacy firewall, deterministic return model,
accessible document structure, offline posture, and equal-dignity final outcomes
can coexist without changing released runtime or curriculum.

The script may dramatize concentration, uncertainty, revision, relief, and
earned confidence. It may not dramatize an exercise answer, a score as moral
worth, a miss as story failure, or a pass as Machine recognition.

## Official-source check

The unavailable local `foundry-azure-source-priority` skill was reported and
the current official Microsoft source was checked directly:

- [Study guide for Exam AI-901: Microsoft Azure AI Fundamentals](https://learn.microsoft.com/en-us/credentials/certifications/resources/study-guides/ai-901)

The guide identifies the audience as a beginning AI-solution developer,
requires conceptual Azure AI knowledge plus foundational Python skills and
Azure-resource familiarity, and divides the current objectives between AI
concepts/capabilities and implementation with Microsoft Foundry. It also notes
REST API, SDK, and CLI familiarity. This confirms the product's combined Python
and AI-901 premise at a high level.

No curriculum mapping reopens. The script must use the existing local objective
codes and approved human-readable topic summaries only. It must not add exam
items, answer keys, pass-score predictions, objective weights as gameplay,
volatile product UI instructions, or a claim that completing the game
guarantees certification.

## Systems reused versus added

### Reused conceptual systems

- Exact fifteen-location pedestrian rail and forty-cluster registry.
- Independent Scene, Pilot, Suit/System, Python, AI-901, save, and readiness
  ownership boundaries.
- Local primary -> feedback -> remediation -> genuinely fresh transfer chains.
- Private/transient clearing and durable finalized-evidence allowlists.
- Atomic save, rollback, deterministic restore, and exact return contracts.
- Equal READY and NOT YET READY outcome geometry and no-exam guarantee.
- Invariant world, no external action, no live service, and `successor=null`.

### New capability

One static UTF-8 Markdown synthesis document. It stores no user state, runs no
code, invokes no service, embeds no generated media, and changes no runtime.

## State and transition constraints

The narrative may represent only this state graph:

```text
LOCATION ARRIVAL
  -> PHYSICAL OBSERVATION
  -> PILOT CONNECTION INTENT
  -> SUIT-OWNED LOCAL WORK
       -> MISS: ACTUAL-GAP FEEDBACK -> ANSWER-FREE REMEDIATION -> BLANK RETRY
       -> PASS: FINALIZED LOCAL EVIDENCE
  -> EXPLICIT SAVE WHERE AUTHORIZED
  -> PILOT WALK OR REVERSIBLE RETURN
```

Every apparent branch converges inside the same cluster. The script cannot
introduce a location branch, skipped cluster, fail ending, fail-forward story
credit, pass-only lore, optional canon, morality state, inventory solution,
Machine verdict, or alternate final scene.

The Route Marker's inherited awake/crowned response remains the sole declared
world-side exception. The script must label it as such and may not foreshadow a
later reward grammar.

## Learning and evidence firewall

For all forty clusters:

- prose may name the skill pressure and emotional experience of attempting it;
- prose may describe that the learner edits, runs, explains, classifies,
  revises, or retries;
- prose may not provide exact case answers, completed code, evaluator keys,
  hidden checks, remediation answers, exam questions, or an answer-bearing
  environmental analogy;
- walking, noticing, connecting, focus, dialogue, reading, time spent, failure,
  retry, save, or story comprehension awards no Python or AI-901 evidence;
- Python and AI-901 evidence remain independently scored where both exist;
- a pass records only the already-approved finalized evidence; and
- a miss records no durable private response and changes only the local working
  loop.

The final Measured Folio may state READY or NOT YET READY only as the released
local-course result over current evidence. It cannot claim exam prediction,
Microsoft approval, certification, access, employment readiness, or service
authority.

## Privacy and persistence

### The script may contain

- stable cluster IDs, objective codes, location names, host names, approved
  evidence categories, and fictional proposed dialogue;
- public official-source links; and
- fictional non-personal Pilot reflections.

### The script must not contain

- real learner responses, notes, names, attempts, diagnostics, scores, tokens,
  endpoints, credentials, payloads, service responses, browser storage, save
  contents, or identity records;
- exam-item text or confidential assessment material;
- protected user-file contents; or
- hidden-lore content or inference.

No runtime or user save is read or mutated to author or validate the document.

## Save, resume, failure, and recovery portrayal

- Working input is transient and clears at approved boundaries.
- Finalized allowlisted evidence saves atomically; the script does not invent
  partial-success persistence.
- Closing a Terminal returns focus and physical orientation to the same host.
- A miss presents actual-gap-only, answer-free remediation in neutral language
  and returns a genuinely blank attempt.
- A malformed or incomplete state fails closed to the first incomplete safe
  boundary without city-refusal language.
- Reload/revisit does not replay arrival, success, conclusion, or world motion.
- Final remediation exposes exact deficient scopes and preserves the same
  canon ending.

## Document accessibility contract

- Use one H1, ordered H2 acts, ordered H3 chapters, and lower headings only
  where needed.
- Do not rely on visual indentation, emoji, color, table position, or typography
  alone for meaning.
- Every diagram receives a prose equivalent immediately before or after it.
- Tables must remain summaries; the complete story must be understandable from
  surrounding prose.
- Expand abbreviations on first meaningful use and keep objective codes paired
  with human-readable learning pressure.
- Mark speaker/owner in text rather than by color or alignment.
- Keep proposed dialogue explicitly labeled so it cannot be confused with
  released runtime copy or native Builder writing.
- Use direct, readable sentences around dense technical ideas and avoid long
  uninterrupted blocks of assessment mechanics.
- The final READY and NOT YET READY variants receive equal heading level,
  length range, dignity, action clarity, and ending image.

## Offline, authority, and external-effect boundary

The document must never imply a live Foundry, Azure, Microsoft, network, model,
agent, endpoint, account, credential, resource, or exam service interaction.
All exercises remain described as local sanitized work. Python syntax and
approved product concepts may be real; service access and external action are
not performed or granted.

Scene, learning, save, and readiness events have `city_state_delta=null`,
`world_response=null`, `authority_delta=null`, and `successor=null`.

## Performance and artifact budgets

Because the output is static documentation:

- one Markdown file, UTF-8, no embedded base64 or generated media;
- target `60-140 KB`, hard maximum `200 KB` unless Mission records a justified
  variance;
- no line above `500` characters except unavoidable Markdown tables;
- no broken local links;
- no duplicate Terminal number or ownership assignment;
- no runtime bundle, CSS, JS, media, build, server, or browser change; and
- patch limited to TE-001 workflow artifacts, the root script, and the
  synchronized handoff.

## Validation ladder

1. **Contract checks:** required sections, ownership language, image-disabled
   boundary, no-successor stop, and proposed-copy labels.
2. **Structural checks:** exactly 4 acts, 15 ordered chapters, and Terminals
   01-40 exactly once with exact ownership codes.
3. **Continuity checks:** every chapter has arrival, walk, discovery,
   connection, learning pressure, meaning, and exit; every exit matches the
   next arrival.
4. **Evidence checks:** no answers, code solutions, exam items, cross-credit,
   fail-forward mastery, or narrative mastery cues.
5. **Privacy checks:** no real learner, save, secret, endpoint, identity, or
   hidden-lore content.
6. **Accessibility checks:** heading order, speaker ownership, prose equivalents,
   non-color meaning, and equal final outcome treatment.
7. **Patch checks:** UTF-8, `git diff --check`, protected-file exclusion, and
   documentation-only scope.
8. **Independent director read:** opening hook, act escalation, midgame
   repetition, Witness pivot, Unborrowed inversion, final chill, and hard stop.

Full runtime tests, browser review, and production builds are not proportionate
for a documentation-only change and must not be claimed.

## Risk register

| Risk | Control |
| --- | --- |
| Forty beats become a lesson catalog | Each chapter receives one dramatic question, sensory identity, inner movement, and closing image |
| Repeated Terminal loop becomes monotonous | Vary scale, sensory channel, discovery owner, inference problem, silence interval, and Pilot reflection |
| Poetry implies hidden lore | Keep every metaphor Pilot-owned and counterbalance it with bounded Suit/Scene language |
| “Failure” reads as punishment | Neutral actual-gap remediation, no story loss, no shame, same canon rail |
| Success reads as Machine approval | Invariant scenery and explicit suit-owned evidence; no celebration grammar |
| Script leaks answers | Describe activity and pressure, never completed code, exact mapping, or evaluator key |
| Final READY sounds like exam certification | Local evidence wording plus explicit no-exam guarantee |
| NOT YET READY feels like a bad ending | Equal dignity, exact next scopes, shared final horizon, no alternate canon |
| World metadata implies planets | Omit legacy World letters from player-facing prose; describe one connected city expedition |
| Novel scope obscures implementation status | Opening note marks the file as canonical game-on-paper, not current runtime parity |

## Flexible areas
