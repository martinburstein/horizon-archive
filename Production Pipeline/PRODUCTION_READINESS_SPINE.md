## Purpose

This spoiler-safe support spine tracks the evidence needed to turn each of the twelve expedition Rail Packets into a protected build, a production-quality visual presentation, a normal integrated route, a Working Team increment, and a releasable accepted demo. It complements `EXPEDITION_SPINE.md`; it does not authorize new story, curriculum, gameplay, code, art, or successor content.

## Readiness gates

- **Protected build:** one end-to-end, offline, non-routable path through real authorities with recovery, save/restore, Tour isolation, and leakage evidence.
- **Production art:** approved first-person maximum-quality cinematic photoreal assets, registered state behavior, provenance, responsive crops, and accessibility alternatives.
- **Normal integration:** an explicitly authorized App/main route, browser persistence boundary, production assets, and responsive full-shell implementation with no accepted-state regression.
- **Working:** Player, bug-repair Coder, Aesthetic, and aesthetic-polish Coder passes over the oldest approved adjacent packet, with exact handoffs and a reloaded demo.
- **Release:** coordinator-focused/full tests, current curriculum validators, production build, full E2E, representative desktop and narrow live review, clean branch, and synchronized backup.

`PASS` means direct evidence exists for the packet's current stage. `DEFERRED` is an explicit later production obligation, not a failure of a protected design gate. `RESERVED` authorizes no content.

## Cross-packet production rules

1. Protected evidence never authorizes normal App/main exposure, browser storage, production art acceptance, Demo credit, Working promotion, or a successor.
2. Production art remains first-person, maximum-quality cinematic photorealistic, physically coherent, and free of the protagonist, ship, hands, shadow, reflection, baked UI, and readable Builder text unless a later approved packet explicitly changes a surface-safe requirement.
3. The `1920 x 1080` check is a future responsive integration acceptance condition, not a fixed-resolution canvas. Narrow, zoomed, and assistive layouts may use natural vertical document flow and must not create horizontal page escape, clipped ownership, smaller targets, or reordered evidence.
4. Presentation, world visibility, layout, focus, motion, review, save status, restore, Tour traversal, and release checks grant zero observation, mastery, access, authority, or exam credit.
5. Reserved rows remain deliberately blank of story, locations, objectives, Python skills, cases, puzzles, routes, art, and code until their contiguous predecessor permits a seed.
