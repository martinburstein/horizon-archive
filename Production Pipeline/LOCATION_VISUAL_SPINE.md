## Visual coverage rules

1. Assign a future location only after its immediate predecessor has a specified player-observable end state and the active Rail Packet authorizes visual development.
2. Every future world plate is first-person, maximum-quality cinematic photorealism with no protagonist, ship, hands, body, shadow, reflection, prior human trace, baked interface, or readable Builder text.
3. Beauty must express Builder function, collective work, material causality, maintenance, and time rather than human ergonomics, generic fantasy, or decorative science-fiction clutter.
4. Each packet's active world plus its current required status and controls must fit one representative full `1920 x 1080` game shell without browser zoom, outer-page scroll, horizontal escape, clipped ownership/copy, or an off-screen required action. Narrow and text-zoom layouts retain accessible vertical reflow.
5. Preserve the largest clean source master, art-directed responsive crops, stable registered geometry, monotonic environmental clocks, reduced-motion equivalents, semantic hotspot alignment, and provenance.
6. Reserved rows authorize no lore, location, concept image, production art, route, code, successor, or chat disclosure. They reserve sequence and visual production capacity only.
7. Update this spine when a packet reaches Storyboard lock, Gate Review, production-art approval, Working promotion, or accepted Demo status—not for every implementation microstate.
