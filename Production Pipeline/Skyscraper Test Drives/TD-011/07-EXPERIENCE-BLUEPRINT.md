## Source-order spatial model

The DOM order remains stable across layouts:

1. skip link;
2. slice landmark (`main`);
3. owner mark;
4. exact phase heading;
5. exact public status (`role=status`, polite, atomic);
6. invariant world region with complete text equivalent;
7. retained-record custody summary;
8. active responsibility content/form;
9. primary action group;
10. permitted returns;
11. offline/no-authority boundary; and
12. optional diagnostics only in the closed fixture, never production.

CSS changes placement, not source order. One `h1`, one main, one status, and
one active owner/group exist at a time. Dense UR-20 and UR-30 work remains in
flow, not in a permanent overlay. Only atomic save confirmation uses a native
modal dialog.

## Focus and announcement lifecycle

### Replacement

After any group replacement, a layout effect resolves
`state.focusIntent.target` inside the slice root and calls focus once. Heading
targets use `tabIndex=-1`. It falls back only to `state.headingId`; missing
both is a contract failure, not silent body focus.

### Same-group update

- Observation accepted: focus the observation-group heading, preserving equal
  availability; after the sixth, focus `ur20-python-primary-source`.
- Case advance: focus the next case's first dimension.
- Recorded revisit or LOOK: focus the current phase heading, not the pressed
  control, so the status is announced without suggesting a new action.
- Missing required field: focus that first blank field; token remains unspent.

### Error/recovery

Commit one complete polite atomic status before focusing the shell-frozen
recovery heading or first invalid field. Error text is field-associated with
`aria-invalid=true` and stable `aria-describedby`. Public failed IDs/tags may
be listed; answers, raw choices, source, prose, or prior record content may not.

### Save confirmation

Open a native `<dialog>` from the triggering review action. Initial focus is
the exact save button frozen by the fixture. Tab remains within save/cancel.
Escape is identical to cancel and writes nothing. During transaction the
dialog closes, the main group owns focus/status, and no action is enabled.

### Restore and returns

- fresh checkpoint restore: `ur30-reopen-rp007` or first unopened scope;
- incomplete local state: first exact incomplete responsibility;
- final checkpoint restore: `ur30-restored-heading`;
- invalid save: earliest exact safe boundary after private clearing;
- Counterfield return: exact released `cf30-restore-heading`;
- City Threshold return: its existing accepted heading/focus contract.

No focus history is persisted or used as evidence.

## Error, retry, cancel, return, and malformed-state rules

- Required blank fields are not errors that spend tokens; status names the
  missing field and focus moves there.
- A scored miss replaces private content with public failed IDs/tags and an
  answer-free Teacher group. Retry reconstructs blank work.
- Route/intent/version/owner/group/action/modality/token mismatch rejects
  before mutation and preserves a future valid token.
- A transaction write/read-back/sanitizer/checksum/predecessor failure either
  proves rollback and presents retry or enters exact hold. No half checkpoint
  or partial record becomes resumable.
- Invalid/extra/private/partial/reordered saves sanitize to null. Recovery
  chooses exact fresh blank UR-10 unless an exact valid checkpoint exists.
- Returns clear private/transient work and are write-free/replay-free. Re-entry
  requires a new route intent. Returns cannot finalize or reopen anything.
- Tour rejects before adapter read/write and exposes no campaign content.

## Responsive geometry

### `1920x1080`

- outer frame uses full available `100dvh`;
- world occupies approximately 58-64% of main width and remains the dominant
  upper/left field;
- active interface occupies 36-42% with max readable line length around 70ch;
- owner/heading/status align at interface start; returns sit after primary
  actions, not in a world hotspot strip;
- six observation buttons may sit over their irregular semantic world regions
  only while remaining in DOM order and equal minimum size.

### `1366x768`

- two-column world/interface remains when content fits;
- world minimum block size preserves laminar thesis and all six region labels;
- dense UR-20/UR-30 work may expand interface width and reduce world width,
  never hide or cover it;
- no outer vertical scroll if current group fits; internal document flow is
  preferable to fixed-height pane scroll.

### `390x844`

- one column: owner/heading/status, compact world, active content/actions,
  returns, boundary;
- semantic observation controls become a six-item list immediately after the
  compact world equivalent; no absolute hotspots or horizontal carousel;
- all controls span available width where helpful and remain >=44px;
- record and reconciliation groups are one column; no side-by-side matrix.

### `768x900 effective at 200% text zoom`

- use the same one-column source order as narrow regardless of CSS pixel
  breakpoint;
- no fixed heights, clipped dialogs, horizontal escape, or text overlay on the
  world;
- dialog width is `min(100% - 2rem, 42rem)` and body may scroll naturally;
- long exact status/provenance copy remains fully present.

Container queries may refine the component, but the four named layouts are
release requirements. Layout cannot change action eligibility, order credit,
focus result, evidence, or record visibility.

## Code-native world and semantic-region plan

The world root is a noninteractive `figure` with exact text equivalent. Its
deterministic CSS children are decorative (`aria-hidden=true`): pressure
laminae, mineral-foam fields, salt-metal seams, ceramic anchors, accretion,
repairs, and unavailable margin. No SVG, canvas, base64, external texture, or
new media is used.

UR-10 adds one semantic observation group after the figure. On wide layouts,
CSS may visually align its six real buttons with irregular world regions using
grid areas; on narrow/zoom it becomes the source-order list. Each button has
the exact shell action label, a short Scene line, a structural state token
`available|recorded`, and no number/rank. Recorded remains an enabled
idempotent button. No visual region itself grants credit.

The unavailable margin is rendered as an ordinary complete material region
without a button embedded in it; the expedition action “RECORD THE UNAVAILABLE
MARGIN” remains the semantic control and grants only the shell observation.

## Record and learning presentation

- retained-four summary: one neutral `section` with explicit count and
  hidden-not-deleted copy; no lock icons or blurred content;
- Python: labelled `textarea`/conceptual select controls in a sealed replica
  section; no run-console illusion, terminal chrome, or output window;
- agent cases: one case at a time, `fieldset` with two labelled native selects;
  progress text is neutral and not a score animation;
- explanations: one labelled text field each; private prose never appears in
  status, record, or logs;
- reopened scopes: one `details`-like controlled group visible at a time, but
  the reopen action itself remains a button and complete content does not
  depend on disclosure-widget memory;
- reconciliation: methods first, limits second, one column, persistent labels,
  no connector/matching lines, no shared-color equivalence;
- saved overview: five record summaries and one separate reconciliation
  summary; no merged card.

## Forced color, reduced motion, grayscale, and modalities

- Forced colors removes decorative world gradients if necessary, preserves a
  bounded world silhouette, uses system borders/background/text, and keeps
  active/recorded/hidden/reopened states explicit in text.
- Reduced motion disables every transition and decorative drift. Replacement,
  focus, status, and evidence remain identical.
- Grayscale review must preserve owner hierarchy, current responsibility,
  observation state, field error, retained/reopened state, buttons, and focus.
- Keyboard Enter/Space activate native buttons. Switch/speech/screen reader
  target the same accessible names and invoke the same intent factory. Pointer
  and touch add no coordinates to semantic state.
