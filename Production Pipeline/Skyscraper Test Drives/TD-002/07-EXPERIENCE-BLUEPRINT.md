## Experience identity

### Player-readable rule

At every boundary the player can determine, from text and native semantics:

1. whether `SYSTEM`, `PILOT`, or `TEACHER` owns the current group;
2. which source-accountability responsibility is current;
3. which actions are available now;
4. which fields are required and still blank;
5. whether a prior exact prefix was finalized locally;
6. how to clear, repair, retry, return, or continue when permitted; and
7. that the City, Machine, Builders, sealed source, and route have not
   responded.

No score, world light, animation, sound, timing, layout, confidence choice, or
presentation state supplies evidence.

### Component envelope

The Combat Engineer should compose:

- the existing invariant `calibration-margin-world` sibling;
- one `CalibrationMarginExtractionFloor` renderer;
- one and only one mounted `ExtractionGroup` at a time;
- one stable polite atomic `ExtractionStatus` inside that group;
- native fieldsets/controls and buttons;
- a pure controller and a storage-agnostic exact-prefix checkpoint adapter;
- a normal-entry composition seam after exact `PY010-P3`; and
- a separate review fixture host outside `src`.

An old group unmounts before the successor receives focus. No replaced form,
answer, repair, status, action, hidden panel, off-canvas group, or
`aria-hidden` control remains operable.

## Source order and control contract

Every authoring group uses this DOM/source order:

1. owner eyebrow and complete phase heading;
2. concise instruction;
3. source/provenance envelope;
4. equal scored dimensions in canonical order:
   `input_boundary`, `output_contract`, `unsupported_rule`;
5. `unsupported_explanation` after the three dimensions at transfer only;
6. optional confidence metadata after all required work;
7. one polite atomic status region;
8. primary action, clear action, and any shell-authorized return;
9. offline/no-authority/no-exam-guarantee boundary.

### Three scored dimensions

Each scored dimension is a native `<fieldset>` with:

- a persistent visible `<legend>`;
- purpose-only help with a stable ID;
- a native radio group whose first state is no selection;
- a unique programmatic name containing group and dimension;
- no checked/default answer, placeholder answer, hidden value, preferred
  order, correctness style, or answer-bearing description; and
- `aria-describedby` linking help and, after incomplete submit, its local
  required error.

The exact candidate labels and values must come from the frozen shared case
presentation authority already used by the protected evaluator. This blueprint
does not reproduce, reorder, or hand-maintain them. The renderer must not
import expected-answer exports.

All three fieldsets are visually equal peers. Position, width, hue, icon,
border, default focus, and animation may not imply a preferred response.

### Separate transfer explanation

`unsupported_explanation` is a required native text control or shell-approved
bounded choice control in its own labelled section after the three dimensions.
It is:

- blank at entry and retry;
- scored separately by the frozen explanation authority;
- never treated as an access request, consent, appeal, confession, credential,
  or service input;
- cleared with the three dimension selections before repair;
- never persisted as prose; and
- committed only as its all-true allowlisted explanation record atomically
  with the transfer record.

### Optional confidence

The optional confidence control uses a labelled native select with blank
default and only `low`, `medium`, and `high`. It is metadata, not a fourth
dimension:

- it is never required and never changes pass, repair, eligibility, focus,
  checkpoint order, or finalization;
- it may enter a successful record only through the existing exact allowlist,
  otherwise it is `null`;
- failed/incomplete attempts, repair, retry, clear, return, replacement, and
  reload destroy it;
- it is never announced as progress and has no success/failure styling; and
- the fixture includes it only as blank/null so no personal response enters
  captures.

### Optional CM-32 reinspection

CM-32 may contain one native `<details>` labelled `Review the source boundary
before the closed-note check`. Its content is fixed, answer-free, and limited
to the difference among supplied course input, requested structured output
with provenance, and unsupported values. Opening/closing it:

- dispatches no controller action;
- writes no marker, token, confidence, attempt, evidence, or diagnostic;
- changes no eligibility and never steals focus from `CONTINUE`;
- is closed on reload/reconstruction; and
- is omitted if Quartermaster cannot produce wording that is demonstrably
  answer-free.

### Submission and miss semantics

- Whitespace-only explanation is incomplete, not an evaluated miss.
- Incomplete submit marks only empty required controls, focuses the first
  invalid control in source order, emits one bounded status, does not call the
  evaluator, and does not spend the event token.
- A complete validated submit invokes frozen truth once.
- An evaluated miss first clears all selections, explanation, confidence,
  evaluator input/result, and event token history associated with the
  attempt. Only then may the Teacher repair group mount.
- Repair contains only the stable canonical order of actual failed dimension
  IDs and, when applicable, `unsupported_explanation`.
- If all dimensions pass and only explanation fails, only the explanation
  boundary appears. If both fail, one ordered union appears.
- Retry is unlimited, untimed, and mounts a new keyed form whose visible,
  native, programmatic, semantic, serialized, focus-history, and live-history
  state is blank.
- A next group mounts only after an exact atomic checkpoint commit succeeds.

## Error, repair, retry, return, resume, and malformed recovery

### Errors

- Required errors are textual, local, and purpose-only.
- Evaluated misses expose only allowlisted failed IDs and approved answer-free
  remediation concepts.
- Missing course input is never described as false, negative, denied,
  corrupted, inaccessible, muted, absent from the City, or permission to
  infer.
- Unexpected exceptions fail closed to the last exact prefix and expose only
  bounded nonprivate reason IDs.
- No raw value, prose, expected value, evaluator object, token, stack, case
  body, media content, credential, endpoint, payload, or response enters
  player copy, logs, diagnostics, captures, or the fixture.

### Retry and cancellation

- Retry is an explicit semantic action and not a form-reset side effect.
- No modal, asynchronous wait, network request, or pending transaction exists.
- `Escape` does not navigate, submit, continue, or retain work.
- `CLEAR_EXTRACTION_WORK` is local clearing, not a route cancel.
- Early route exit exists only at primary, primary repair, and interlude.
- Retrieval, retrieval repair, transfer, transfer repair, and final landing
  have no return, cancel, close, or Escape route.

### Return

- P0 return clears all IE private/transient state, writes nothing, and restores
  exact Python landing.
- P1 interlude return preserves only exact P1 and clears disclosure, focus,
  status history, token, and any transient metadata.
- Re-entry uses another fresh `BEGIN_EXTRACTION`; P1 reconstructs interlude
  rather than replaying primary.
- Return never changes Python, observations, IE credit, attempt count, save,
  review, route, City, access, authority, or world state.

### Checkpoint failure

- A failed P1 append restores exact P0/Python landing after clearing work.
- A failed P2 append preserves P1 and reconstructs interlude.
- A failed atomic P3 append preserves P2 and reconstructs blank transfer plus
  blank explanation.
- No failure downgrades a valid prefix, leaves a partial record, or mounts a
  success group before commit.

### Malformed or contaminated state

- Exact keys, version, shell, packet, mapping, prefix, ordered all-true record
  set, bounded metadata, null deltas, unchanged continuation, and null
  successor are mandatory.
- Unknown keys, false dimensions, duplicate/out-of-order records, private
  values, transfer without explanation, explanation without transfer, Python
  or observation records, save/review/route content, or later-state content
  rejects the whole candidate.
- Exact predecessor plus malformed IE sanitizes to `IE-P0`.
- Invalid predecessor routes to the existing first-incomplete Python recovery
  owner.
- Recovery never reflects contaminated content and never replays evidence.
