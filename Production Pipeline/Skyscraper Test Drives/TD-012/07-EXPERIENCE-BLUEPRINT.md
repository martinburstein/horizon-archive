## Fresh forms and remediation flow

Python uses one labelled blank private source/editor region with exact local
validator warning; it is not a console or live runtime. AI-901 uses one
objective responsibility at a time in exact shell order with native labelled
controls. Neutral progress may state “objective 4 of 15” but is never a score,
percent, timer, readiness estimate, or answer cue.

After the fifteenth objective, the controller atomically derives the exact
ordered 16 Boolean set. If false gates exist, private work clears and only
their exact remediation IDs become public. After every route is completed,
retry reconstructs only the false-gate forms blank. A still-false retry loops
to remediation; all repaired gates advance to decision. Earlier true gates
remain finalized but never populate current controls.

## Focus and announcement lifecycle

### Replacement

On group replacement, resolve `state.focusIntent.target` inside the slice and
focus once. Heading targets use `tabIndex=-1`. Fallback is only the declared
heading ID; missing both is contract failure, never body focus.

### Same-group behavior

- Evidence disclosure: focus its heading; disclosure state grants no credit.
- Objective advance: focus next objective’s first control.
- Missing input: announce exact field, focus it, leave token unspent.
- Route revisit/unchanged rejection: focus current heading after status.
- Outcome remediation selection: focus exact route heading, not outcome title.

### Recovery

Commit one complete polite atomic status, then focus the exact remediation
route or invalid field. `aria-invalid` and stable `aria-describedby` associate
errors. Public failed IDs may render; answers/source/choices/private notes may
not.

### Save modal

Native `<dialog>` contains exact save and cancel. Initial focus is
`mh40-save-readiness`; Tab remains inside. Escape equals cancel, writes
nothing, and returns focus to invoking save-request control. Transaction
closes the dialog, moves status/focus to `mh40-transaction-heading`, and
disables every action.

### Restore and returns

- restored ready -> `mh40-saved-review-heading`;
- restored not-yet -> first exact remediation route;
- valid incomplete current state -> first exact incomplete/invalid gate;
- invalid save -> MH-10 heading after private clearing;
- Unborrowed Reach return -> exact `ur30-restored-heading`;
- City Threshold return -> existing accepted heading.

No focus history persists or credits anything.

## Malformed state, cancel, and transaction rules

- Intent mismatch rejects before mutation/token spending.
- Empty required field is recoverable in place and not scored.
- Scored miss clears private controls and retains only public false IDs.
- Extra/missing/reordered/private/forged/stale save sanitizes to null.
- Write/read-back/checksum/predecessor failure either proves rollback and
  offers retry or enters exact hold. No partial checkpoint resumes.
- Save cancel/Escape returns to the exact outcome with identical state.
- Returns clear transient/private work and write/replay nothing; re-entry
  requires fresh route intent.
- Tour rejects before adapter access and cannot render normal groups.

## Code-native world and folio regions

The world is one noninteractive `figure` with complete text equivalent. Its
CSS decorative layers are `aria-hidden`: existing laminae, mineral foam,
salt-metal seams, ceramic anchors, accretion, and unavailable margin. No SVG,
canvas, image/data URI, external texture, or new media.

The folio is semantic HTML:

- `header` for owner/objective version;
- `nav` only for individually navigable evidence/remediation destinations,
  never world travel;
- `section` for one current leaf;
- `fieldset` for objective responsibilities;
- native buttons for every action;
- `dl` for saved audit basis and limits; and
- one contained native save dialog.

Datum rules and tabs are CSS decoration/borders inside the expedition layer.
They never extend into world geometry or point toward a destination.

## Common outcome anatomy

public state token, measurements, focus order, palette, borders, and action

## Forced colors, reduced motion, grayscale, modalities

- Forced colors removes decorative gradients if needed, preserves bounded
  world silhouette, uses system colors/borders, and retains explicit text for
  every gate/outcome/route/focus state.
- Reduced motion sets all transitions/animations to none; replacements,
  status, focus, evidence, and outcome remain identical.
- Grayscale preserves owner hierarchy, current leaf, errors, tabs, outcome,
  buttons, and visible focus.
- Native keyboard actions work with Enter/Space; switch/speech/screen reader
  use identical accessible names and intent factory; pointer/touch add no
  semantic coordinates.
