## Transaction, failure, sanitation, and recovery

### Intent and adapter

`SAVE EXPEDITION NOTE` accepts exactly these activation kinds:

```text
pointer
touch
keyboard_enter
keyboard_space
switch
speech
screen_reader
```

The intent is exact-keyed, campaign-owned, private-free, shell/version bound,
action bound, and protected by one opaque fresh token. Validation precedes
token consumption.

The adapter must:

1. capture the last verified serialized value without parsing it into
   permissive state;
2. construct and strict-sanitize the complete candidate;
3. serialize only the sanitized candidate;
4. perform one atomic replacement through the dedicated key;
5. read the committed value through the same strict sanitizer;
6. accept success only when canonical sanitized read-back equals the
   candidate; and
7. expose only the sanitized immutable result.

A thrown, unavailable, quota-limited, rejected, partial, stale, duplicate,
forged, Tour-derived, contaminated, malformed, or read-back-invalid attempt
must not become accepted state. The adapter's failure contract preserves the
last known-good serialized bytes exactly; tests must prove this with a
pre-existing valid record and with no prior record.

### Clearing

Clear private and transient material on:

- rejection;
- failed write;
- retry;
- successful replacement;
- successful read-back;
- return;
- reload sanitation;
- invalid recovery; and
- completion.

Clearing covers active responses, source drafts, answers, feedback,
confidence controls, review/save tokens, focus history, transaction
diagnostics, and private reason text. Only bounded public reason codes may
survive transiently for accessible status.

### First-incomplete routing

Validation order is fixed:

1. observation IDs;
2. Python primary, retrieval, transfer;
3. IE primary, retrieval, transfer, unsupported explanation;
4. provenance;
5. no-external-action invariant;
6. provenance inspection; and
7. save transaction.

| Missing/invalid observation | first incomplete CM-10 observation control |
| Invalid Python record | exact first incomplete blank CM-20, CM-22, or CM-23 boundary |

Recovery never downgrades, duplicates, recomputes, cross-credits, or erases
